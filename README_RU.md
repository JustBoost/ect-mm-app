# Прямоугольник мм

Маленькое Android-приложение (Flutter): рисует на экране телефона прямоугольник заданного
**физического** размера в миллиметрах и заданного цвета. Сделано под OnePlus 5T
(Android 9/10, экран 1080 × 2160, около 401 точки на дюйм), но работает на любом телефоне.

- Экран настроек: ширина (по горизонтали экрана) и длина (по вертикали) в мм, цвет R, G, B (0–255).
  У каждого параметра ползунок и числовое поле, они синхронизированы. Шаг размеров 0,5 мм,
  диапазон ползунка 1…(размер экрана по этой оси, округлённый вниз до целого мм).
  Умолчания: 30 × 50 мм, цвет 255, 255, 255 (белый).
- Под параметрами: образец цвета и строка «Экран: X × Y мм (xdpi …, ydpi …)».
- «Показать» — полноэкранный режим: чёрный фон, системные панели скрыты, прямоугольник строго
  по центру; экран не гаснет. Касание экрана или кнопка «Назад» — обратно к настройкам,
  значения сохраняются (только в памяти: после закрытия приложения — снова умолчания).
- Если размер больше экрана — в настройках красное предупреждение, а в полноэкранном режиме
  прямоугольник не уменьшается, а обрезается краями экрана. С клавиатуры можно ввести до 1000 мм.
- Только портретная ориентация. Разрешений приложение не запрашивает.

## Как считается размер

`физические пиксели = мм / 25,4 × dpi`, где dpi — реальная плотность пикселей экрана:
`xdpi` для ширины, `ydpi` для длины. Их сообщает Android
(`resources.displayMetrics.xdpi/ydpi`) через канал `rect_mm/screen` из `MainActivity.kt`.
Если значение явно неправдоподобно (меньше 100 или больше 1000), берётся `densityDpi`, и в
настройках об этом пишется красным. Логические пиксели Flutter = физические / devicePixelRatio.
Размер прямоугольника доводится до целого числа физических пикселей той же чётности, что и
экран (чтобы по центру он ложился ровно на сетку пикселей и края были резкими) — это меняет
размер не больше чем на 1 пиксель, около 0,06 мм при 401 dpi.

Пример: 25,4 мм при 401 dpi = 401 физический пиксель = 152,76 логических при devicePixelRatio 2,625.

## Структура

```
pubspec.yaml                 зависимости: только flutter, flutter_test, flutter_lints 5.0.0
analysis_options.yaml        правила анализатора
lib/main.dart                запуск, только портрет, MaterialApp
lib/mm.dart                  чистые функции: мм <-> пиксели, шаг 0,5, разбор и вывод чисел
lib/screen_info.dart         xdpi/ydpi и размер экрана из MainActivity (канал rect_mm/screen)
lib/settings_page.dart       экран настроек (ползунки + поля, предупреждение, «Показать»)
lib/fullscreen_page.dart     полноэкранный режим с прямоугольником
test/mm_test.dart            юнит-тесты формулы и вспомогательных функций
test/widget_test.dart        тесты экранов (канал замокан: 401 dpi, экран 1080 × 2160, DPR 2,625)
android/                     Gradle-проект (версии Gradle 8.14.5 / AGP 8.11.1 / Kotlin 2.2.20 — как в
                             проверенной сборке), пакет MainActivity com.andrey.rect_mm,
                             applicationId com.andrey.rectmm
android/app/src/main/kotlin/com/andrey/rect_mm/MainActivity.kt   канал rect_mm/screen
.github/workflows/build.yml  сборка в GitHub Actions
```

`gradlew`, `gradlew.bat` и `gradle-wrapper.jar` в репозитории не хранятся (как и в проверенной
сборке-образце, они в `.gitignore`): Flutter сам кладёт обёртку Gradle при `flutter build apk`.

## Сборка (GitHub Actions)

Файл `.github/workflows/build.yml`. Запускается на каждый push в любую ветку, кроме `builds/**`,
и вручную (Actions → build → Run workflow). Окружение: ubuntu-latest, Java 17 (zulu),
Flutter 3.44.8 stable. Шаги:

1. `flutter create --platforms=android --org com.andrey --project-name rect_mm .` — страховка:
   дописывает только отсутствующие файлы каркаса, существующие не трогает. Затем удаляются
   шаблонные `*.gradle.kts`, если рядом есть наши `*.gradle`, и проверяется, что MainActivity ровно один.
2. `flutter pub get`, `flutter analyze --no-fatal-infos`, `flutter test`, `flutter build apk --release`.
3. Результаты кладутся в ветку `builds/<имя ветки без claude/>` (например, `claude/rect-app` →
   `builds/rect-app`): `rect_mm-release.apk` и его SHA-256, `analyze.txt`, `test.txt`,
   `build_tail.log`, `flutter_create.txt` (что дописал flutter create), `STATUS.txt` (коды шагов).

Release подписан отладочным ключом (как в стандартном шаблоне Flutter). Ключ отладки создаётся
на машине сборки заново, поэтому APK из нового прогона может не встать поверх старого
(«Приложение не установлено», конфликт подписи) — тогда удалить старое и поставить заново.

## Установка на телефон

1. Скачать `rect_mm-release.apk` из ветки `builds/<ветка>` (на GitHub: выбрать ветку → файл →
   Download raw file) прямо на телефон или на компьютер.
2. Вариант через компьютер: включить на телефоне «Для разработчиков» → «Отладка по USB», затем
   `adb install -r rect_mm-release.apk`.
3. Вариант без компьютера: открыть APK на телефоне и разрешить установку из этого источника
   (Настройки → Приложения → Специальный доступ → Установка неизвестных приложений).
4. В списке приложений — «Прямоугольник мм».

## Известные ограничения

- **Точность зависит от того, насколько честно телефон сообщает xdpi/ydpi.** Часть прошивок
  отдаёт округлённые или «типовые» значения. Обязательно проверить линейкой: например, задать
  50 × 100 мм и приложить линейку к стеклу по обеим осям. Значения, которые использует
  приложение, видны в строке «Экран: … (xdpi …, ydpi …)». Если линейка расходится, поправку
  можно внести вручную в размер (или, при необходимости, добавить в приложение поправочный коэффициент).
- Если телефон не ответил по каналу (например, запуск не на Android), размер оценивается по
  devicePixelRatio (160 × DPR) и может заметно отличаться — об этом пишется красным.
- Края экрана с закруглёнными углами или вырезом обрежут прямоугольник, близкий к размеру экрана.
- Значения не сохраняются между запусками приложения (по требованию — только в памяти).
- Локально приложение не собиралось и тесты не прогонялись (в среде разработки нет Flutter SDK);
  первая проверка — прогон CI.
